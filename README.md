# Pixel Art Creator

Pixel art as code, for any project. Sprites, tiles, items and frame-by-frame
animations are drawn by TypeScript and built into PNGs plus a JSON manifest.
Two Claude Code agents do the drawing. The style comes entirely from **your
reference images**, measured the same way every time, so every project gets
the same quality of setup whatever it looks like.

Nothing here has a built-in look. The only fixed rule is that the output is
pixel art.

```
your-project/
├─ .claude/agents/
│   ├─ sprite-artist.md         sprites, tiles, items, bulk jobs, the style setup
│   └─ character-animator.md    frame-by-frame characters and animations
└─ pixel-art/                   the kit (copy this whole folder)
    ├─ STYLE.md                 your project's art rules (starts UNSET)
    ├─ REFERENCES.md            the style setup protocol: references → measured → STYLE.md
    ├─ ANIMATION.md             the animation method (redraw from a reference)
    ├─ references/              your reference images (never shipped, git-ignored)
    ├─ overrides/               hand-painted PNGs that replace generated ones
    └─ src/
        ├─ engine/              the drawing engine (don't edit per project)
        ├─ tools/               build, preview, anim, analyze, dump
        └─ art/                 YOUR art: style.ts, palette.ts, sprites/, anims/, registry.ts
```

## Install into a project

1. Get the kit and copy it in (from the project's root folder):

   ```sh
   git clone https://github.com/novadesignsllc/pixel-art-creator /tmp/pac
   cp -R /tmp/pac/pixel-art .
   mkdir -p .claude/agents && cp /tmp/pac/.claude/agents/*.md .claude/agents/
   rm -rf /tmp/pac
   ```

   The copy belongs to that project from then on: its art, style and
   references live there. To pick up a newer kit later, copy over
   `pixel-art/src/engine/` and `pixel-art/src/tools/` only (never `src/art/`,
   `STYLE.md` or `references/`, which are the project's own).
2. `cd pixel-art && npm install` (needs Node 20+).
3. Add this to the project's `CLAUDE.md`:

   ```md
   ## Art
   All pixel art is generated by code in `pixel-art/`. Its rules live in
   `pixel-art/STYLE.md` (authoritative). Sprites, tiles, items, bulk art and
   style changes → the `sprite-artist` agent. Characters and animation →
   the `character-animator` agent. Never copy pixels from `pixel-art/references/`.
   ```
4. Put reference images in `pixel-art/references/<style|lighting|palette|animation|subject>/`
   and ask Claude to "set up the art style". The sprite-artist runs the
   setup in `REFERENCES.md`: a few questions, measuring every reference, a
   fixed checklist per reference, filling `STYLE.md`, then a calibration
   board for you to approve before any real art is made.

The kit is self-contained: it has its own `package.json` and doesn't touch
the host project's build. It works next to any stack (web, React Native,
Unity, Godot, native mobile), because what it produces is plain PNGs and a JSON file.

## Commands (run in `pixel-art/`)

| command | does |
|---|---|
| `npm run analyze` | measure every reference → `out/analysis/` (reports, images, `SUMMARY.md`) |
| `npm run analyze -- <id>` | just one reference |
| `npm run analyze -- --ours calibration` | measure our own sprites with that tag, the same way, next to the references |
| `npm run build` | all art → PNGs + `manifest.json` in `PROJECT.outDir`; review sheets in `out/sheets/` |
| `npm run preview -- <name>` | one sprite at 8x and 1x (tiled 3x3 if it's a texture); `--bg #hex`, `--zoom N` |
| `npm run preview -- 'block-*'` | a labeled contact sheet (also `tag:<tag>`) |
| `npm run preview -- --board` | references vs the calibration set, same zoom |
| `npm run anim -- <name>` | one animation: film strip, onion skin, GIF, compare with its reference, motion table; `--ship` also builds |
| `npm run dump -- <ref-id> --frames 0,1 --region x0,y0,x1,y1` | a reference as letter grids, one letter per color |
| `npm run check` | typecheck |

## How it works

**Sprites.** A sprite is a function that returns a `Raster` (an RGBA pixel
grid). You draw with letter grids (`fromGrid`: one character per pixel) or
shapes, using only colors from `src/art/palette.ts`, and finish with the
project's outline. Register it in `src/art/registry.ts` and `npm run build`
writes the PNG. Randomness is seeded by the sprite's name, so rebuilds are
pixel-identical.

**Bulk.** `family({ prefix, items, make })` turns one generator plus a list
(inline or a JSON file in `src/art/specs/`) into hundreds of sprites, each
named from the list. You fix the generator, not 500 drawings.

**Style.** `STYLE.md` holds the rules in words; `src/art/style.ts` and
`palette.ts` hold the same rules as numbers the build applies (outline,
ramp rule, the optional lighting pass, sizes). Both start empty and are
filled from your references.

**References → numbers.** `npm run analyze` undoes upscaling, cleans JPEG
noise, finds the background, then measures: material ramps (colors that
touch and are related), cooler/warmer hue shifts, outline type and color,
light direction (from the shading inside each material), shades per
material, dithering, detail (same-color cluster size), tile size, and for
animations a per-frame motion table plus letter-grid dumps. Fixed
thresholds, no randomness: the same image always gives the same numbers.
The agent then answers the same checklist for every reference while looking
at the review images, and fills STYLE.md from a fixed decision table.
`--ours` measures your own art the same way, so "does it match?" is a
comparison of numbers, not a feeling.

**Animation.** Characters are letter-grid parts (head, torso, legs...)
drawn into each frame with offsets measured from a reference animation,
redrawn only where the shape changes. A reference is required: motion
invented from a description comes out stiff. See `ANIMATION.md`.

**Overrides.** A PNG in `overrides/` named like a sprite ships instead of
the generated one. Hand edits always win, and the agent learns from them.

## The manifest

`manifest.json` is the contract with your app:

```json
{
  "baseScale": 1,
  "scales": [1],
  "tileSize": 16,
  "sprites": {
    "crate": { "file": "crate.png", "w": 14, "h": 14, "anchorX": 0.5, "anchorY": 1, "tags": ["prop"] },
    "block-granite": { "file": "block-granite.png", "w": 16, "h": 16, "anchorX": 0, "anchorY": 0, "texture": true, "meta": { "material": "granite" } }
  },
  "anims": {
    "hero-walk": {
      "file": "hero-walk.png", "frameW": 32, "frameH": 32, "frames": 8, "fps": 10, "loop": true,
      "anchorX": 0.5, "anchorY": 0.875, "facings": { "s": "hero-walk-s.png" }, "mirror": { "w": "e" }
    }
  }
}
```

Sizes are in art pixels. Animation sheets are one row of frames, left to right.

## Pixel art on each platform

Pixel art must be scaled by whole numbers with **nearest-neighbor**
filtering, or it blurs.

- **Web canvas / PixiJS / Phaser:** `baseScale: 1`, `exportScales: [1]`;
  set nearest filtering (`image-rendering: pixelated` in CSS,
  `texture.source.scaleMode = 'nearest'` in PixiJS, `pixelArt: true` in Phaser).
- **Unity / Godot:** import with Filter Mode = Point (Unity) or
  Nearest (Godot), compression off; slice sheets by `frameW` × `frameH`.
- **React Native / native iOS & Android:** their image views smooth pixels
  when they scale, so let the build do the scaling: in
  `src/art/project.ts` set `baseScale` to the points per art pixel you want
  (e.g. 3) and `exportScales: [1, 2, 3]`. You get `name.png`, `name@2x.png`,
  `name@3x.png`; the OS picks the right one for the screen and draws it 1:1.
  Size each image at `w × baseScale` points. For free scaling and
  rotation, draw with `@shopify/react-native-skia` and nearest sampling
  instead.

A starting point for an animation in React Native (a sketch, not tested in
an app; adapt it to your project):

```tsx
import { useEffect, useState } from 'react';
import { Image, View } from 'react-native';
import manifest from './assets/sprites/manifest.json';

// Metro needs static requires: keep one line per sheet you use
const SHEETS: Record<string, number> = {
  'hero-walk': require('./assets/sprites/hero-walk.png'),
};

export function SpriteAnim({ name }: { name: keyof typeof manifest.anims }) {
  const a = manifest.anims[name];
  const [frame, setFrame] = useState(0);
  useEffect(() => {
    const t = setInterval(
      () => setFrame((i) => (a.loop ? (i + 1) % a.frames : Math.min(i + 1, a.frames - 1))),
      1000 / a.fps,
    );
    return () => clearInterval(t);
  }, [name]);
  const w = a.frameW * manifest.baseScale;
  const h = a.frameH * manifest.baseScale;
  return (
    <View style={{ width: w, height: h, overflow: 'hidden' }}>
      <Image
        source={SHEETS[name]}
        style={{ width: w * a.frames, height: h, transform: [{ translateX: -frame * w }] }}
      />
    </View>
  );
}
```

## Licensing and references

- The kit's code is yours to use in any project.
  Dependencies: `pngjs` (MIT), `gifenc` (MIT), `sharp` (Apache-2.0).
- **References are not part of the kit and never ship.** Image files in
  `pixel-art/references/` are git-ignored. Each reference records its
  `rights` (`own`, `licensed`, `style-only`), and the agents follow them:
  `style-only` references are measured and looked at, never traced or
  redrawn frame by frame. If you share or sell this kit, share it without
  anyone's reference images.
